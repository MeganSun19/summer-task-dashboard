# 双星学习岛

一个给两个 7 岁孩子共同使用的家庭学习工作台。产品的首要目标不是记录更多数据，而是：

> 让孩子看得懂今天做什么、知道怎么做、能自己完成并获得反馈，从而尽量减少家长提醒和陪同。

项目原名“假期学习工作台”。当前产品名为“双星学习岛”，哥哥和弟弟各有独立身份、任务进度和阳光账户，共同参与学习岛的成长。

## 核心用户

- 哥哥：角色为《如果历史是一群喵》的乌龙，拥有自己的今日任务、完成状态、连续天数和阳光。
- 弟弟：角色为哈小浪，拥有与哥哥相互独立的同类数据。
- 家长：制定计划、处理异常、查看结果，不负责逐项催促。

双孩子机制以合作为主，不设置公开排名，避免形成固定的赢家和输家。未来两人通过完成个人任务共同建设花园。

## 产品原则

1. **孩子首页只关注今天**：不给孩子复杂日历和统计压力。
2. **每项任务都说明“怎么做”**：把家长口头提醒写进任务卡。
3. **先独立、后求助**：不会的内容先圈出，完成其余部分后再统一求助。
4. **即时正反馈**：每完成一项立即获得阳光和清晰反馈。
5. **挫折可恢复**：漏做不会永久摧毁资产，后续可通过补做恢复。
6. **家长只看异常**：家长视图优先显示尚未开始、剩余任务和错题。
7. **计划与展示分离**：课程计划来自可维护数据，前端只负责按日期落实。

## 每日核心流程

### 孩子

1. 选择哥哥或弟弟。
2. 从第一张任务卡开始，阅读“今天做什么”和“怎么做”。
3. 完成后点击按钮，获得 10 阳光。
4. 依次完成剩余任务；卡住的内容先圈起来。
5. 全部完成后点亮学习岛。

### 家长

1. 打开家长总览，查看两个孩子的实时进度。
2. 只处理没有开始、剩余任务或错题等异常。
3. 必要时修改当天任务及孩子看到的操作步骤。
4. 记录需要进入后续复习的错词和错题。

## 当前每日模块

- 英语 RAZ
- 写字练习
- 古诗背诵
- 数学练习：乘除法、100 以内加减法
- 课外书阅读
- 英语听力：Big Muzzy / 英文版《西游记》

## RAZ 计划

RAZ 日计划以以下工作簿为准：

`../outputs/raz_bf_catalog/raz_b_to_f_catalog.xlsx`

其中：

- `4-Week Plan`：28 天计划，包含主题、书目、目标词、句型和家长提示。
- `Catalog`：B–F 级 470 本书的目录和字数信息。
- `Word-Book Map`：目标词与适合书目的映射。
- `Parent Guide`：读前、读中、读后的执行建议。

当前前端内置了这份 28 天计划，并按项目开始日期循环映射到每日任务。RAZ 卡片将计划转换成孩子可执行的步骤：

1. 先听一遍。
2. 自己指读。
3. 找出目标词。
4. 用当天句型说一句。

后续需要把工作簿内容转换为独立数据文件或后台数据，避免课程数据长期硬编码在 `app.js` 中。

## 激励系统规划

当前只有一种货币：阳光。每项任务完成获得 10 阳光。孩子可以在奖励中心自行发起兑换申请：

1. 申请后对应阳光立即冻结，避免重复花费。
2. 家长在家长中心选择同意或退回。
3. 同意后兑换完成；退回后阳光自动返还。
4. 家长可以新增自定义奖励和设置价格。

默认奖励为选择今晚的故事、动画时间、家庭游戏和小惊喜。

后续的学习岛游戏遵循：

- 个人阳光目前用于现实奖励，未来再加入角色装扮。
- 两人全部完成时为共享花园增加能量。
- 漏做任务会让僵尸前进一步，但不会永久删除孩子已经获得的植物。
- 补做任务可以唤醒植物或击退僵尸。
- 第一阶段不引入多种货币，避免规则复杂化。

## 数据模型

目标结构：

```text
家庭
├── 哥哥
│   ├── 每日任务
│   ├── 完成记录
│   └── 阳光账户
└── 弟弟
    ├── 每日任务
    ├── 完成记录
    └── 阳光账户
```

当前浏览器本地状态大致为：

```js
{
  version: 1,
  startDate: "YYYY-MM-DD",
  activeKid: "brother",
  rewards: [],
  redemptions: [],
  days: {
    brother: { "YYYY-MM-DD": { tasks: [], mistakes: "", note: "" } },
    younger: { "YYYY-MM-DD": { tasks: [], mistakes: "", note: "" } }
  }
}
```

本地存储键为 `summer-task-dashboard-v1`。该模型是过渡实现，后续迁移到 Supabase。

云端第一阶段使用同样的数据形状保存在 `family_states.state` 中，并通过 `families`、`family_members` 和 RLS 限制为家庭成员可读。每次写入带 `revision`，发现其他设备已经更新时会重新载入，避免无提示覆盖。

## 技术与部署目标

- 静态前端部署到 CloudBase 免费体验环境的静态网站托管。
- Supabase 负责云端存储与多手机同步。
- 工作台不依赖家中电脑保持开机。
- 家人可从任意手机打开同一个家庭空间。
- 第一阶段优先使用家庭邀请码或设备 PIN，而不是让孩子管理账号密码。

## 成功指标

核心指标：两个孩子能否在尽量少的家长提醒下完成当天计划。

建议后续记录：

- 每天家长主动提醒次数。
- 孩子独立完成任务的比例。
- 首次打开到开始第一项任务的时间。
- 卡住后能否继续完成其他任务。
- 每周全完成天数，不比较两个孩子的排名。

## 本地运行

这是一个无构建步骤的静态页面：

```bash
cd summer-task-dashboard
python3 -m http.server 4173
```

然后访问 `http://127.0.0.1:4173`。

直接打开 `index.html` 也能使用，但本地服务器更接近 CloudBase 的实际运行方式。

## Supabase 初始化

项目的公开连接配置位于 `supabase-config.js`。这里仅允许使用 publishable key，不能放入 secret 或 `service_role` key。

首次启用云端：

1. 在 Supabase Dashboard 打开 **SQL Editor**，新建查询。
2. 粘贴并执行 `supabase-schema.sql` 的完整内容。
3. 打开 **Authentication → Providers → Anonymous Sign-Ins**，启用匿名登录。
4. 刷新双星学习岛，点击顶部云端状态。
5. 第一台设备选择“创建并上传本地数据”，设置 4–8 位家长 PIN。
6. 记下生成的 8 位家庭邀请码；其他设备通过邀请码和 PIN 加入。

匿名账号只作为设备身份，孩子不需要管理账号密码。家庭数据由 RLS 和家庭成员关系保护；PIN 只用于批准新设备加入，不会保存明文。
