# 双星学习岛

## 家庭空间与同步原则

- 一个家庭邀请码对应一份独立云端数据；所有设备必须显示同一个邀请码。
- 设备会记住明确选择的主家庭。若本机加入过多个家庭但主家庭记录丢失，必须人工选择，绝不自动进入任意旧家庭。
- 加入或切换家庭时，按日期、孩子、任务 ID 和状态更新时间合并；完成、当天有效免除、学习日、阳光解锁与英语活动进度都采用不丢失合并。
- 免除状态只对 `excusedOn` 对应的具体日期生效，不会继承到同名任务的后续日期。
- 云端写入使用 revision 乐观锁；切换家庭前停止旧家庭的延迟写入，避免跨家庭污染。
- 旧家庭不会自动删除。当前正式主家庭是 `67690F58`，其他邀请码仅保留为历史恢复来源。

一个给两个 7 岁孩子共同使用的家庭学习工作台。产品的首要目标不是记录更多数据，而是：

> 让孩子看得懂今天做什么、知道怎么做、能自己完成并获得反馈，从而尽量减少家长提醒和陪同。

项目原名“假期学习工作台”。当前产品名为“双星学习岛”，哥哥和弟弟各有独立身份、任务进度和阳光账户，共同参与学习岛的成长。

## 核心用户

- 哥哥：角色为《如果历史是一群喵》的乌龙，拥有自己的今日任务、完成状态、连续天数和阳光。
- 弟弟：角色为哈小浪，拥有与哥哥相互独立的同类数据。
- 家长：制定计划、处理异常、查看结果，不负责逐项催促。

双孩子机制以合作为主，不设置公开排名，避免形成固定的赢家和输家。未来两人通过完成个人任务共同建设花园。

## 产品原则

1. **孩子首页只关注今天**：不给孩子复杂日历和统计压力。
2. **每项任务都说明“怎么做”**：把家长口头提醒写进任务卡。
3. **先独立、后求助**：不会的内容先圈出，完成其余部分后再统一求助。
4. **即时正反馈**：每完成一项立即获得阳光和清晰反馈。
5. **挫折可恢复**：漏做不会永久摧毁资产，后续可通过补做恢复。
6. **家长只看异常**：家长视图优先显示尚未开始、剩余任务和错题。
7. **计划与展示分离**：课程计划来自可维护数据，前端只负责按日期落实。
8. **计划与实际分离**：暑假计划按完成的学习日推进；未完成内容持续顺延，不能因自然日期变化而跳过。

## 每日核心流程

### 孩子

1. 选择哥哥或弟弟。
2. 从第一张任务卡开始，阅读“今天做什么”和“怎么做”。
3. 完成后点击按钮，获得 10 阳光。
4. 依次完成剩余任务；卡住的内容先圈起来。
5. 全部完成后点亮学习岛。

### 家长

1. 打开家长总览，查看两个孩子的实时进度。
2. 只处理没有开始、剩余任务或错题等异常。
3. 在“长期课程”中设置某个孩子每天默认显示的项目、名称和操作步骤。
4. 在“临时任务”中发布一次性、连续、隔日或自选日期的家庭安排。
5. 在“今日调整”中修改单日内容、完成状态，以及需要后续复习的错词和错题。
6. 在“已发布计划”中查看、编辑或取消临时任务，并管理生病、旅行等特殊时期的日期区间计划。

## 暑假计划后的长期产品方向

双星学习岛不是只服务于当前暑假计划的一次性工具。第一期 26 个内容学习日完成后，产品应继续作为家庭长期学习工作台使用；当前课程只是第一期内容，不应成为任务模型、页面结构或课程生成方式的固定边界。

### 暑假计划的实际推进规则

- 哥哥和弟弟各自拥有独立的当前学习日；一个孩子的进度不阻塞另一个孩子。
- 当天任一必做任务未完成，下一自然日继续显示同一个学习日和已有完成状态，不生成后续学习内容。
- 当前学习日全部完成后，当天保持完成画面；下一自然日才进入下一个学习日。
- 家长可把确实无法完成的项目标记为“特殊情况免除”；免除不增加阳光，但视为本学习日已处理，可解除进度卡点。
- 每项完成记录保存实际完成日期；阳光只在真实完成时获得一次，顺延和免除不会重复奖励。
- 两个孩子的阳光分别按各自已完成任务计算；升级不清零现有阳光。植物达到门槛后记录为永久解锁，之后即使取消任务导致当前阳光下降也不会重新上锁。
- 双星世界地图按两人完成同一个逻辑学习日配对，不再要求两人在同一个自然日完成。
- 云端首次载入会合并本机较新的完成记录；每次保存写入更新时间，避免尚未上传的勾选被旧云端快照直接覆盖。
- 每台设备首次升级都会把本机尚未上传的完成记录合并进家庭云端；多设备同时修改发生冲突时，按任务更新时间合并并自动重试。学习日取较靠后的进度，历史完成任务、家长临时任务和英语岛活动记录均保留。
- 旧版“特殊情况免除”只导入一次；没有更新时间的旧免除状态不能覆盖云端当前设置，避免已取消的写字免除反复出现。
- 已连接错误家庭空间的设备可使用“切换并合并学习记录”：目标家庭作为统一云端，本机历史日期、完成任务、较靠后的学习日、英语岛记录与植物解锁一并合并；原家庭空间保留，不执行删除。

### 当前第一优先级：学习模块解耦

- 学习模块基础解耦已于 2026-08-07 完成；下一阶段课程和新模块应沿用这套协议，不再回到页面硬编码。
- 孩子端只依赖统一的任务/模块协议，例如模块标识、标题、执行步骤、内容数据、资源、完成条件和奖励；不直接写死“自然拼读”“RAZ”“古诗”等具体学科逻辑。
- 具体学习内容由课程数据或家长发布数据决定。增加、移除、替换模块时，应优先通过配置和数据完成，而不是修改首页任务流程。
- 模块可以拥有各自的交互渲染能力，但注册、排期、展示、完成记录和奖励等公共能力由统一框架负责，避免每增加一种学习内容就复制一套流程。
- 当前英语、古诗和数学任务已经接入通用模块结构；后续阶段继续沿用同一协议，并保留既有完成记录和孩子端体验。
- 后续不得把新的课程阶段、模块名称、日期规则或内容分支重新硬编码进 `app.js`。

当前实现边界：

- `curriculum/learning-module-catalog.json`：模块目录的唯一手工维护入口，保存模块身份、默认展示信息和互动 renderer 声明；古诗、数学等逐日课程内容由 Excel 生成，不在这里重复维护。
- `curriculum/learning-module-catalog.js`：由 JSON 确定性生成的浏览器产物，不直接编辑。运行 `node scripts/generate-learning-module-catalog.mjs` 重建，运行同一命令加 `--check` 校验产物没有漂移。
- `curriculum/summer-plan-content.json` / `.js`：由总表的“古诗计划”确定性生成 26 个实际学习日的孩子端任务内容；数学不预设固定日内容，由家长每天填写。
- `learning-modules.js`：稳定的通用模块协议，负责任务标准化、默认任务生成和展示信息查询。
- `learning-plan-presets.js`：日期区间计划的可注册变换规则；新增计划模板不修改任务主流程。
- `LearningActivityProgress`：通用互动模块进度接口，按孩子、日期和模块保存开始时间与活动进度；旧 `englishExperiment` 字段只作为兼容别名保留。
- `legacy-learning-plan.js`：只承载 2026 年 8 月 3–6 日历史计划，避免临时日期逻辑继续留在 `app.js` 主流程。
- `app.js`：只编排日期、孩子、任务展示、完成记录、奖励和家长设置，不再定义默认学科内容。

### 灵活发布家庭任务

- 第一版已于 2026-08-07 完成：支持一次性、连续每天、隔一天和自选日期，可指定哥哥、弟弟或两人，并在发布前预览实际日期。
- 每条安排使用独立 `taskId`、`scheduleId`、`source` 和 `moduleId`；编辑或取消只影响尚未完成的每日实例，历史完成记录保留。
- 家长中心可以发布一次性临时任务，并指定孩子、执行日期、任务说明和完成方式。
- 临时任务也可以覆盖一个短周期并设置非连续节奏。例如“学习学校要求的一支舞蹈”可以安排 3–4 次、隔一天学习一次，而不必改写孩子的长期课程。
- 临时任务与长期课程并存，到期后自然结束，不影响后续课程计划。
- 家长可以在发布前预览任务实际出现在哪些日期；发布后仍可调整或取消尚未执行的安排。

### 后台规划长期课程

- 第一版课程发布基础已于 2026-08-07 完成：按孩子保存草稿、预览每日模块、生成不可变发布版本并设置生效日期。
- 每日任务按孩子和日期选择已生效的最新版本；发布不会重建过去日期、单日人工调整、区间计划或已有课程完成记录的日期。
- 草稿和发布版本记录本阶段目标及可选的预计结束日期；历史版本可复制为新草稿，经重新预览与发布实现安全回退，旧版本本身保持不可变。
- 阶段结束日期是目标检查点，不会让每日课程突然停止。若下一阶段尚未发布，孩子端继续沿用当前版本；新版本到达生效日后自动接管，避免课程空档。
- 后台支持从一个总体学习目标出发，按阶段、周期和每日任务逐级拆解课程，并将计划发布到孩子端。
- 每一期课程有明确的目标、起止范围、适用孩子、学习模块和日程；新一期可以替换、增删或调整模块，而不要求修改孩子端的固定页面逻辑。
- 孩子端仍只呈现“今天做什么、怎么做”，复杂的目标拆解、排期和内容维护留在后台完成。
- Excel 总表生成、模块引用校验和发布前冲突检查已经接入发布脚本；编辑中的草稿不会直接影响孩子端。

### 英语课程按阶段演进

- 当前 26 天英语课程用于打基础，包含自然拼读、心词/高频词、RAZ 阅读迁移和听力输入。
- 进入下一学习阶段后，英语目标和每日模块应重新规划。例如自然拼读完成阶段使命后可以退出日常任务，并由新的学习内容接替。
- 前端不能把“自然拼读”或当前 26 天结构视为永久必备模块；课程内容应由当期计划驱动。

### Excel 总表是课程规划入口

- 所有后台规划的学习内容最终汇总到 Excel 总表，以总表作为课程审核、排期和发布的主要事实来源。
- 总表至少需要表达课程阶段、总体目标、日期或相对学习日、适用孩子、任务模块、学习内容、执行步骤及所需资源。
- 发布流程应依据总表生成前端可读取的课程数据，并在生成前进行完整性和日期冲突检查，避免长期把课程内容硬编码在 `app.js` 中。
- 临时家庭任务不必先进入课程总表；它属于家长中心的灵活发布层，但在孩子端应与计划课程统一展示和完成。

当前生成链路：

- `../outputs/course-master-foundation-20260807/家庭长期课程总表.xlsx` 保留英语内容、音频、心词和来源工作表，并增加“课程阶段、课程模块、模块字典、古诗计划、数学每日填写”。古诗从原第 11 周接续；数学表仅用于家长记录当天实际安排，不预设固定内容。

- 运行 `python3 scripts/generate-summer-plan-content.py` 生成古诗 JSON 与浏览器 JS；加 `--check` 会确认古诗恰好覆盖 Day 1–26，且产物与 Excel 完全一致。数学由家长在孩子端“今日调整”填写，可同步记入“数学每日填写”工作表。

### 可复用的音频生产能力

- 当前“根据课程词条生成 TTS 音频，再写入课程和静态音频包”的思路可复用于后续英语阶段及其他需要朗读的内容。

## 本地运行

这是一个无构建步骤的静态页面：

```bash
cd summer-task-dashboard
python3 -m http.server 4174
```

然后访问 `http://127.0.0.1:4174`。

首次测试只需进入“英语岛”，点击“开始今天的英语岛”。课程引用的静态音频会直接从 `course-audio/` 加载，不需要选择本机文件。

直接打开 `index.html` 也能使用，但本地服务器更接近 CloudBase 的实际运行方式。

试听审核必须通过上述本地服务器运行，因为优先清单不会公开部署：

第 2–4 周课程短候选使用独立页面，不需要重新导入 Oxford 音频包：

```text
http://127.0.0.1:4174/audio-review.html?week=4
```

页面顶部可切换第 2、3、4 周；各周审核进度分别保存在当前浏览器。点击“重听片段”后人工选择“正确 / 单词错误 / 边界错误 / 暂时跳过”，完成一周后导出对应 JSON。页面直接读取 `tmp/course-audio-review/week-{2,3,4}/clips/` 中已经生成的短片段，不把机器转写结论当作人工审核结果。

以下步骤仅用于旧的整轨/首周审核流程：

1. 在家长中心先导入需要审核的 Oxford Disc 文件夹或 ZIP；若已配置家庭云端，也可直接使用另一台设备已经上传的音轨。
2. 打开“优先试听审核”，默认从 Level 1、P0“核心词 + 低置信度”开始。
3. 点击“重听片段”，选择“正确 / 单词错误 / 边界错误 / 暂时跳过”；错误项可在备注中写正确词或边界问题。
   - 机器显示词本身不对（例如把字母串或前导词当成单词）选“单词错误”；词正确但片段多带、少带或截断声音选“边界错误”。四个按钮默认都是未选择状态，只有已保存的结论会高亮。
4. 审核结果保存在当前浏览器；阶段性点击“导出审核结果 JSON”备份。误操作可切到“已审核”后撤销本条。
5. 第一轮完成后选择“问题待复核”。系统只列出“单词错误”和“边界错误”，并自动扩大播放上下文；改判为“正确”后会从问题列表移除，不需要重审已确认条目。

完成复核并导出 JSON 后，可生成只含人工确认片段的 Level 1 数据：

```bash
node scripts/build-opw-verified-clips.mjs '../outputs/<审核结果文件>.json'
```

输出为 `curriculum/opw-level1-verified-clips.json`。仍标记为单词错误、边界错误或跳过的候选不会进入该文件；原始 Oxford MP3 不会被修改或删除。

首周审核结果使用独立回写命令：

```bash
node scripts/apply-week1-review-results.mjs '/Users/megsun/Downloads/opw-week1-review-results-2026-08-04.json'
```

命令会把通过项写入 `curriculum/opw-week1-review-state.json`，重建首周课程，并只把修订项保留在试听清单中。修订项使用新的 `-r2` 审核 ID，因此浏览器里的第一轮结论不会误判为第二轮已完成。

当前浏览器若尚未导入某张 Disc，面板会显示缺少的具体 Level、Disc 和 Track，不会改用其他音轨。

## CloudBase 部署

部署脚本锁定现有 CloudBase 环境。`--english` 发布到验收路径，`--main` 发布到正式主入口；省略参数时默认使用验收路径。发布前会先校验模块目录 JavaScript 与 JSON 数据源完全一致，再重建 26 天课程、为缺失词生成并自动接纳 TTS，最后从课程 JSON 生成最小静态音频包。目录产物过期或数据结构无效时发布会立即停止。

部署前先登录 CloudBase CLI：

```bash
npx --yes --package=@cloudbase/cli@latest cloudbase login
```

然后运行：

```bash
./deploy-cloudbase.sh --english

# 验收通过后覆盖正式主入口
./deploy-cloudbase.sh --main
```

脚本只发布课程实际引用的资产，不上传六张光盘的完整 300+ MB 资源。已验证 Oxford 片段继续保留；生成的 TTS 自动进入发布包，人工录音仍需审核。

## Supabase 家庭同步

Supabase 只负责家庭邀请码、计划和进度同步。Oxford 课程音频不再经过家庭 Storage，也不受 owner 设备角色影响；任何打开已发布页面的孩子设备都直接读取同一套 CloudBase 静态音频。
